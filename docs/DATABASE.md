# Database Documentation

Stockox uses a PostgreSQL database hosted on Supabase. The database acts as the single source of truth for all business data.

## Entity Relationship Overview
- A `User` has one `Portfolio` and many `Watchlists`.
- A `Portfolio` has many `Portfolio Holdings`.
- A `User` initiates many `Analysis Sessions`.
- An `Analysis Session` has many `Agent Messages` and one final `Recommendation`.

---

## Tables Details

### `users`
Stores user profile data synced from Clerk.
- `id` (VARCHAR): Primary key, internal user ID.
- `clerk_id` (VARCHAR): Unique identifier provided by Clerk.
- `email` (VARCHAR): User's email.
- `name` (VARCHAR): Full name.
- `role` (VARCHAR): User's permission role (e.g., 'Lead Investment Advisor').

### `portfolios`
Stores the high-level summary of a user's holdings.
- `id` (UUID): Primary key.
- `user_id` (VARCHAR): Foreign key to `users`.
- `total_value` (DECIMAL): Sum of cash balance and all holding values.
- `cash_balance` (DECIMAL): Available uninvested cash.
- `daily_change` (DECIMAL): Absolute change in value today.
- `daily_change_percent` (DECIMAL): Percentage change.

### `portfolio_holdings`
Stores individual assets owned within a portfolio.
- `id` (UUID): Primary key.
- `portfolio_id` (UUID): Foreign key to `portfolios`.
- `ticker` (VARCHAR): Asset symbol (e.g., 'AAPL').
- `quantity` (DECIMAL): Number of shares owned.
- `average_price` (DECIMAL): Average purchase price.
- `current_price` (DECIMAL): Last known market price.

### `watchlists`
Assets tracked by the user.
- `id` (UUID): Primary key.
- `user_id` (VARCHAR): Foreign key to `users`.
- `ticker` (VARCHAR): Asset symbol.
- `company_name` (VARCHAR): Name of the tracked company.

### `analysis_sessions`
Represents an AI Committee analysis run.
- `id` (UUID): Primary key.
- `user_id` (VARCHAR): Foreign key to `users`.
- `ticker` (VARCHAR): Asset symbol analyzed.
- `recommendation` (VARCHAR): BUY, HOLD, or SELL.
- `confidence_score` (INTEGER): 0-100 score of conviction.
- `risk_level` (VARCHAR): LOW, MEDIUM, or HIGH.

### `agent_messages`
Individual responses generated by specific agents during a session.
- `id` (UUID): Primary key.
- `analysis_session_id` (UUID): Foreign key to `analysis_sessions`.
- `agent_name` (VARCHAR): 'Research Agent', 'Risk Agent', etc.
- `message` (TEXT): The markdown or JSON payload of the agent's findings.

### `agents`
Tracks the global state/status of agents for UI feedback.
- `id` (UUID): Primary key.
- `name` (VARCHAR): Name of the agent.
- `status` (VARCHAR): Current operational status ('idle', 'thinking', etc).

### `recommendations`
A formalized snapshot of the committee's decision.
- `id` (UUID): Primary key.
- `analysis_session_id` (UUID): Foreign key to `analysis_sessions`.
- `ticker` (VARCHAR): Asset symbol.
- `recommendation` (VARCHAR): BUY, HOLD, or SELL.
- `target_price` (DECIMAL): Expected price target.

### `market_snapshots`
Cached snapshot of high-level market indices.
- `id` (UUID): Primary key.
- `symbol` (VARCHAR): e.g., 'SP500', 'BTC'.
- `price` (DECIMAL): Last price.
- `change_percent` (DECIMAL): Percentage change.

---

## Constraints and Indexes
- Foreign key constraints use `ON DELETE CASCADE` to ensure orphaned records (e.g., holdings of a deleted portfolio) are removed automatically.
- Extensive indexing is applied to `deleted_at` (for soft deletes), `user_id`, `ticker`, and `analysis_session_id` for query optimization.
